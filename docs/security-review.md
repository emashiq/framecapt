# Security and reliability review (phase 09)

Date: 2026-10-02. Reviewed: the code as committed after phase 08 plus the changes of this phase (everything below cites
`file:line` of the tree after the fixes). Method: every `handle(...)` registration and every `sendEvent` call was read in
full, then each preload, window, session, protocol, filesystem and child-process path; findings were fixed in code with
regression tests where they were medium or higher (and for most low ones), the rest are documented as residual risk.

Companion documents: `docs/performance.md` (benchmark), `docs/architecture.md` (process model), `docs/recording-persistence.md`
(session format and recovery policy), `docs/decisions.md`.

## 3. IPC: every channel

Chokepoint: `handle()` in `src/main/ipc.ts:40` is the **only** place that touches `ipcMain` (a test fails if any other
file calls `ipcMain.on/once/handle/...`). Per call it checks, in order: (1) the sender is a registered `webContents` with
an allowed role (`getRole`), (2) the frame is the **top** frame and its URL is inside the app (`checkSender`,
`src/main/ipc-core.ts:34`, `isAppUrl` in `src/main/app-origin.ts:16`: `file:` below the renderer folder, or the dev-server
origin in development), (3) the payload parses with the channel's strict schema (`runChannel`, `ipc-core.ts:56`); anything
the handler throws that is not an `IpcError` becomes a generic `INTERNAL`. The handler roles must be a subset of the
contract's, and a test requires equality. `tests/unit/ipc-security.test.ts` runs the role/frame matrix against **all 68
channels** (every role x top/sub frame x good/foreign URL).

Roles: `main` = the app window, `overlay` = selection overlays, `toolbar` = recording controls, `recorder` = the hidden
capture window, `countdown` = the 3-2-1 window. Payload column: field names of the strict schema; `bytes` fields are
`ArrayBuffer` with a size cap. "Path?" says whether the request can carry a path, URL or command: **no** unless stated.

## 4. Preload, navigation, permissions, CSP

- **Preload** (`src/preload/index.ts`): one object, `framelet`, with `invoke` (name checked by `isIpcChannel`, an `own-property`
  test that also rejects `__proto__`/`constructor`; only the first argument is forwarded) and `on` (`isIpcEvent`; the
  listener receives the **payload only**, never the `IpcRendererEvent`; returns an unsubscribe). `ipcRenderer` itself is
  not exposed. Tested by loading the real preload with a recording `electron` (`ipc-security.test.ts`, "preload"), and in
  the packaged app (`npm run smoke:packaged`: bridge keys are exactly `invoke,on`, no Node globals, unknown channel refused).
  Prototype pollution: payloads are validated by strict schemas that never merge into existing objects; 400 rounds of random
  junk including `{"__proto__": ...}` leave `Object.prototype` untouched (same file).
- **Window preferences** (`src/main/windows.ts:110`): `contextIsolation`, `sandbox`, `webSecurity` true; `nodeIntegration`,
  `webviewTag`, `allowRunningInsecureContent`, `spellcheck` false; `devTools` only when unpackaged; `nodeIntegrationInWorker`,
  `nodeIntegrationInSubFrames` and `experimentalFeatures` are not set and default to false in Electron 44 (`electron.d.ts`).
  Every window (main, overlay, toolbar, countdown, hidden recorder) is built from `securePreferences()`; `app.enableSandbox()`
  (`src/main/index.ts:36`) covers any future one. Tested: `window-security.test.ts`.
- **Navigation** (`src/main/security.ts:15-35`), registered once on `app.on('web-contents-created')` so it covers **every**
  webContents (main, overlays, toolbar, countdown, recorder, any future one): `will-navigate`, `will-redirect` and
  `will-frame-navigate` are cancelled unless the target is an app URL; `will-attach-webview` is cancelled;
  `setWindowOpenHandler` denies everything. There is **no `shell.openExternal`** anywhere in `src` (grep), so there are no
  external links to validate; `shell.openPath` is only used for history media (S-03) and the chosen output folder
  (`settings:openOutputDir`, a main-owned path). `shell.showItemInFolder` takes main-owned paths (R-01).
- **CSP** (`src/shared/csp.ts`): `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:
blob: framelet-media:; media-src 'self' blob: mediastream: framelet-media:; font-src 'self'; connect-src 'self'; base-uri
'none'; form-action 'none'; frame-ancestors 'none'; object-src 'none'`. Delivered **both** as a response header
  (`installCsp`, `security.ts:46`, dev server) **and** as a `<meta>` tag injected at build time
  (`vite.renderer.config.ts`); since phase 10 the `app://` protocol handler also sends the policy as a response header. Development adds only the dev-server origin and an
  inline script for React refresh (`devCsp`); the packaged app was checked to carry the meta tag (smoke test). The one
  loosening is `style-src 'unsafe-inline'` (R-03).
- **Permissions** (`security.ts:59-99`, `app-origin.ts:67-86`): request and check handlers allow only `media` (microphone:
  a request that includes `video` is denied, the app has no camera feature) and `clipboard-sanitized-write`, and only for app
  URLs. Everything else is denied: geolocation, web notifications (the app's own OS notifications are made by main, `desktop.ts:155`, with fixed text), MIDI, HID, serial,
  USB, Bluetooth, clipboard-read, fullscreen, pointer lock, idle detection, `display-capture`, `openExternal`... (table test).
  Display capture is not a permission prompt: `setDisplayMediaRequestHandler` (`capture/authorization.ts:24`) answers only
  from a main-made one-shot grant bound to the requesting webContents/top frame/app URL, otherwise `{}`. Device choosers
  are cancelled (S-08).
- **No remote content, no network**: the renderer loads `file:` assets and `framelet-media:` only (fonts are bundled);
  `connect-src 'self'` and the session blocker (S-08) cancel every http(s)/ws(s)/ftp request, so there is nothing to
  upload, update-check or report to. Verified in the packaged app: a `fetch('https://example.com')` from the page fails.
  There is no telemetry code (`grep -rn "fetch(\|XMLHttpRequest\|WebSocket" src` finds nothing).

### `framelet-media:` (`src/main/recording/media-protocol.ts`)

Privileges: `standard, secure, stream` only (no `bypassCSP`, no CORS, no fetch API). Resolution
(`resolveMediaUrl`, line 68) accepts exactly three shapes and nothing else: `//<registry id>` (a recording this run wrote),
`//thumb/<history id>` and `//file/<history id>` (+ one optional lowercase `[0-9a-z]{1,24}` cache-busting segment). The id
is a uuid matched by a regex **before** any lookup; the lookup is a `Map` get (main-made ids -> main-known paths). No
query, hash, user, port, extra segment, path or drive letter can name a file, whatever its encoding (`%2e%2e`, `%5c`,
double-encoding, UNC, absolute drive paths: 30+ shapes in `media-protocol.test.ts`, each answered 404/400 with
`Cache-Control: no-store`, none reaching the disk). The response is served only for `.webm .mp4 .mkv .png .jpg .jpeg`
and only for **regular files**; GET/HEAD only (405 otherwise); `Range` is a single `bytes=a-b | a- | -n` range parsed by
`range.ts` (anything else is ignored, an unsatisfiable start is 416, the end is clamped to the file). There is no listing:
the scheme has no index route.

## 5. Filesystem, child processes, fuses, mocks, logging

**Write locations** (all main-chosen): `userData/recordings/<uuid>/{manifest.json, stream.webm}` (manifest: temp file, fsync,
rename; stream: append handle, fsync on close), `recordings/completed/<id>.json`, `userData/history/{history.json, thumbs/}`
(`writeFileAtomic`: temp, fsync, rename, `src/main/shots/atomic-write.ts:9`), `userData/shots/<uuid>/original.png`,
`userData/settings.json` (atomic, debounced), `userData/logs/main.log` (2 MB rotation), `userData/diagnostics/` (R-04), and
the **user-chosen** screenshot/recording/MP4 locations, which come only from main-process save/folder dialogs (plus a write
probe, `settings/output-dirs.ts:30`). Finished recordings are published by `rename` of a partial file in the same folder;
an existing file is never overwritten (`freeTarget`). Exports use a `.partial` name made by main.

**Deletions** (every `rm`/`trashItem` in `src/main`): a session folder whose name is a uuid inside the recordings root
**and** is a real directory (not a link) **and** whose manifest names the same id (`recovery.ts`, `session-service.ts:dirFor`),
the single `.framelet-<id>.partial.webm` a manifest names when it equals the expected name (and is absolute), screenshot
session folders by uuid (`shots/session-store.ts`: containment re-checked, `sweep` uses `Dirent` so links are skipped,
7-day age, `keep` marker), thumbnails by `<uuid>.png`/leftover patterns (`history/thumbs.ts`), and temp files this call
made. **User files are only ever moved to the Recycle Bin** (`shell.trashItem`, `history/service.ts:360`), on an explicit,
confirmed action; "remove from history" never touches the file; nothing deletes an export. `fs.rm` on a link removes the link.

**FFmpeg** (`src/main/media/ffmpeg.ts`): the binary path comes only from `resolveFfmpeg` (packaged:
`resources/ffmpeg/win32-x64`; development: `vendor/ffmpeg/...`; never PATH, never renderer input); `spawn(file, args,
{ shell: false, windowsHide: true, stdio: ['ignore','pipe','pipe'] })` with argument **arrays** (line 168); inputs and
outputs are absolute main-made paths (`mediaPath`), so they can never start with `-`; inputs are opened with
`-protocol_whitelist file` and a forced demuxer where the format is known (S-02); every run has a timeout (remux 10 min,
probe 30 s, export `max(10 min, 4 x duration)`) and an `AbortSignal`; abort/timeout kill the **tree** (`taskkill /T /F`).
After a main-process crash ffmpeg exits by itself (its progress pipe closes): measured in the failure-mode exercise (4a:
no orphan 0.6 s after the kill). The only other `spawn` is the Squirrel installer hook (`src/main/squirrel.ts:18`,

## 13. Phase 10 changes (packaging, app:// scheme, updates)

- **R-02 closed.** The production renderer is served from `app://framelet` (`app-asset.ts`: pure resolver; `app-protocol.ts`: handler). The scheme is `standard` + `secure` only. The resolver refuses other schemes/hosts/ports/credentials, dot segments (checked on the URL as written, because the URL parser folds `/a/../x` silently), percent-encoded and double-encoded traversal, backslashes, NUL, `:`, empty segments and unknown extensions, and re-checks containment after `path.resolve`. Unit tests (`tests/unit/app-asset.test.ts`) cover these cases; an e2e test fetches refused URLs through the real handler; `isAppUrl` (IPC sender checks, permissions, display-media authorization, navigation lockdown) accepts exactly `app://framelet`.
- **Fuse off.** `GrantFileProtocolExtraPrivileges` is disabled in `forge.config.ts`; `smoke:packaged` and `smoke:installed` read the fuse back from the exe and load the UI.
- **Installer defects found by running it.** (1) Squirrel downloaded an `<iconUrl>` from raw.githubusercontent.com during install: an offline machine waited about 85 s; removed (ADR-034). (2) `--squirrel-firstrun` was treated as an obsolete hook and quit the app; it now starts normally. (3) The launch-at-login entry is removed on uninstall (needs a ready app, so the hook waits for `ready`).
- **Network.** Neither the app nor its updater makes a request: the update adapter is `unconfigured` (no autoUpdater call); 60 s runs of the e2e build and of the installed app saw zero non-loopback TCP connections, no request outside app/framelet-media/blob/data schemes, and nothing for the network blocker to cancel. The only network access during packaging is the build-time FFmpeg and Electron downloads (hash-pinned).
- **Not changed / open.** The installer and executables are UNSIGNED, so Windows SmartScreen will warn (owner action: certificate). Squirrel's own stub (about 3.8 MB) remains after uninstall. CI actions are pinned to major versions, not SHAs (hardening option). Signing and a configured update feed were not exercised (no certificate, no feed).
