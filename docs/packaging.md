# Packaging, install and uninstall

Phase 10. Everything here was built and run on the build host (Windows 11 Pro 10.0.26300, x64, interactive desktop); the exact artifact hashes and install/uninstall results are in `docs/evidence/phase10/` (`artifacts.json`, `installed-smoke.json`, `network-e2e.json`). **The installer and the executables are UNSIGNED**: no certificate exists, so Windows SmartScreen will warn when the installer is run. See [release-process.md](release-process.md) for signing.

## What `npm run make` produces

| Artifact                                                            | Notes                                                                                         |
| ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `out/make/squirrel.windows/x64/Framelet-Setup-<v>.exe`              | Squirrel.Windows per-user installer (about 229 MB; FFmpeg alone is about 211 MB uncompressed) |
| `out/make/squirrel.windows/x64/Framelet-<v>-full.nupkg`, `RELEASES` | Update payload for a Squirrel feed (not used while no feed is configured)                     |
| `out/make/zip/win32/x64/Framelet-win32-x64-<v>.zip`                 | Portable zip: unzip and run `Framelet.exe`                                                    |
| `out/Framelet-win32-x64/`                                           | The unpacked packaged app (what both of the above contain)                                    |

`npm run record:artifacts` writes sizes, SHA-256 and the installer's Authenticode status to `docs/evidence/phase10/artifacts.json` and `out/make/SHA256SUMS.txt`. No MSI is built (`noMsi`). Builds are not bit-for-bit reproducible (the archives embed timestamps); the Electron zip and FFmpeg downloads are pinned by SHA-256.

`premake` runs `scripts/clean-build.mjs` (removes `.vite`, so a leftover E2E/mock build can never be packaged) and `scripts/fetch-ffmpeg.mjs` (idempotent, hash-verified).

## Packaged layout

```
Framelet.exe                         Electron runtime, fuses applied, icon + version info (company/product PROVISIONAL)
resources/app.asar                   .vite/build/main.cjs, preload.cjs, renderer (index.html + assets)
resources/ffmpeg/win32-x64/          ffmpeg.exe, ffprobe.exe, LICENSE, PROVENANCE.json, README.txt
LICENSE, LICENSES.chromium.html      Electron / Chromium notices
```

The FFmpeg folder is `resources/ffmpeg/win32-x64/` (Packager copies `extraResource` entries by base name, so the brief's shorthand `resources/ffmpeg/ffmpeg.exe` is not the real path). `resolveFfmpeg()` uses exactly this path, never `PATH`.

How resources resolve when packaged: the renderer is served by the `app://framelet` protocol from `app.asar`; the preload is `app.asar/.vite/build/preload.cjs`; FFmpeg is found through `process.resourcesPath`. Verified on the installed app: the UI renders, `ffmpeg ok 9.0.2` is logged at start, a real recording is remuxed with the bundled FFmpeg and exported to H.264 MP4.

Fuses (read back from the **installed** exe by `smoke:installed`): RunAsNode off, cookie encryption on, NODE_OPTIONS off, `--inspect` off, embedded asar integrity on, only load from asar, **`GrantFileProtocolExtraPrivileges` off**.

## Identity (PROVISIONAL)

`forge.config.ts` marks these as provisional; the owner must confirm or replace them before any public release: product name `Framelet`, publisher/company `Framelet contributors`, app id `com.framelet.app` (packager `appBundleId`, non-Squirrel AppUserModelID), Squirrel package id `Framelet` (also the install folder and the Squirrel AppUserModelID `com.squirrel.Framelet.Framelet`), the placeholder icon `assets/app/framelet.ico` (generated by `scripts/generate-tray-icons.mjs`, original artwork, 16-256 px).

## Install (per user, no administrator rights)

`Framelet-Setup-<v>.exe` (interactive) or `Framelet-Setup-<v>.exe --silent`:

| What                                                | Where                                                                                                                                                                |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Program files                                       | `%LOCALAPPDATA%\Framelet\app-<version>\` plus `Update.exe`, the `Framelet.exe` launch stub and `packages\`                                                           |
| Start Menu shortcut                                 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Framelet contributors\Framelet.lnk`                                                                                 |
| Desktop shortcut                                    | `%USERPROFILE%\Desktop\Framelet.lnk` (created by Squirrel)                                                                                                           |
| Programs and Features entry                         | `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\Framelet` (runs `Update.exe --uninstall`)                                                                  |
| Launch at login (only when switched on in Settings) | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `com.squirrel.Framelet.Framelet`: `Update.exe --processStart Framelet.exe --process-start-args --hidden` |

Observed on this host: a silent install takes about 6 s. **A silent install does not start the app** (Squirrel launches the app with `--squirrel-firstrun` only after an interactive install); `smoke:installed` therefore starts `Framelet.exe --squirrel-firstrun` itself to prove that flag starts the UI normally (it used to quit: fixed).

Squirrel runs the app with `--squirrel-install` / `--squirrel-updated` (create shortcuts and exit), `--squirrel-uninstall` (remove shortcuts and the launch-at-login entry, exit) and `--squirrel-obsolete` (exit); `src/main/squirrel.ts` handles them without starting the UI (spawn with `shell: false`).

### Defect found and fixed: the installer made a network request

electron-winstaller's default nuspec has an `<iconUrl>` that Squirrel downloads while installing (for the Programs and Features icon). With no route to raw.githubusercontent.com the install waited **about 85 s** for a timeout. An offline app should not touch the network while installing, so `assets/app/framelet.nuspectemplate` omits it: the install now takes about 6 s and Programs and Features shows a generic icon until the owner hosts an https icon (`iconUrl`).

### Defect found and fixed: launch at login did not start the app

Following the Electron docs literally (`args: ['--processStart', '"Framelet.exe"', '--process-start-args', '"--hidden"']`), Electron 44 writes the arguments quoted and escaped, so Update.exe was asked to start a file named `"Framelet.exe"` (with the quote characters) and nothing started. Measured: the quoted form starts nothing, the plain form (`--processStart Framelet.exe --process-start-args --hidden`) starts the app. `loginItemOptions` passes plain arguments; `smoke:installed` switches the setting on in the installed app, reads the Run value, executes it like Windows does and checks that the app starts hidden in the tray.

## Uninstall

`Update.exe --uninstall -s` (also what Programs and Features runs). Verified on this host:

- Removed: the program files, both shortcuts, the Programs and Features entry, the launch-at-login entry.
- **Kept on purpose**: `%APPDATA%\Framelet` (settings, history database, unfinished sessions, logs: the user's data, and a reinstall continues where it left off) and every capture folder (`Pictures\Framelet`, `Videos\Framelet`, or the folders chosen in Settings). The uninstall never touches them: `smoke:installed` puts sentinel files in both default capture folders and in `%APPDATA%\Framelet` and checks them afterwards.
- Known Squirrel.Windows behavior, not a Framelet defect: the running updater cannot delete itself, so about 3.8 MB remain in `%LOCALAPPDATA%\Framelet` (`Update.exe`, a `.dead` marker, `app-<v>\squirrel.exe`) and an empty `Framelet contributors` Start Menu folder is left. No Framelet file (exe, asar, FFmpeg) remains. Deleting that folder by hand is safe.

To remove user data as well, delete `%APPDATA%\Framelet` after uninstalling (the capture folders are yours: delete them only if you mean to).

## Data locations

| Location                                         | Holds                                                                                     | On uninstall           |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------- | ---------------------- |
| `%LOCALAPPDATA%\Framelet`                        | The program (Squirrel)                                                                    | removed (stub remains) |
| `%APPDATA%\Framelet`                             | `settings.json`, history, `recordings`/`shots` sessions, `logs\main.log`, Chromium caches | **kept**               |
| `Pictures\Framelet`, `Videos\Framelet` (default) | Screenshots, recordings, MP4 exports                                                      | **kept**               |
| `HKCU\...\Run`                                   | Launch at login entry (optional)                                                          | removed                |

Output folders can be moved in Settings; the app never deletes a capture on uninstall, history cleanup or export.

## Network behavior

Framelet makes no network request by itself (no telemetry, no cloud, no update check). Measured, not assumed:

- e2e build, 60 s of use (`tests/e2e/network.spec.ts`): 0 requests outside app/framelet-media/blob/data, 0 requests for the app's own network blocker to cancel, every TCP connection of the process tree loopback-only (10 samples). A positive control (a main-process request to an https address) is observed and cancelled, so the zero is a real measurement.
- Installed app, 60 s including a recording and an MP4 export (`smoke:installed`): no non-loopback TCP connection in the whole process tree (10 samples), nothing for the blocker to cancel.
- Updates are unconfigured: `autoUpdater` is never even loaded (unit test).
- Outside the app: the build downloads Electron and FFmpeg (hash-pinned); with no `iconUrl` the installer downloads nothing.

`npm run make` and `npm run check:mocks`, `npm run smoke:packaged`, `npm run smoke:installed` (all described in [testing.md](testing.md) and [release-process.md](release-process.md)).
