# Packaging, install and uninstall

Phase 10. Everything here was built and run on the build host (Windows 11 Pro 10.0.26300, x64, interactive desktop); the exact artifact hashes and install/uninstall results are in `docs/evidence/phase10/` (`artifacts.json`, `installed-smoke.json`, `network-e2e.json`). **The installer and the executables are UNSIGNED**: no certificate exists, so Windows SmartScreen will warn when the installer is run. See [release-process.md](release-process.md) for signing.

## What `npm run make` produces

| Artifact                                                             | Notes                                                                                         |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `out/make/squirrel.windows/x64/FrameCapt-Setup-<v>.exe`              | Squirrel.Windows per-user installer (about 229 MB; FFmpeg alone is about 211 MB uncompressed) |
| `out/make/squirrel.windows/x64/FrameCapt-<v>-full.nupkg`, `RELEASES` | Update payload for a Squirrel feed (not used while no feed is configured)                     |
| `out/make/zip/win32/x64/FrameCapt-win32-x64-<v>.zip`                 | Portable zip: unzip and run `FrameCapt.exe`                                                   |
| `out/FrameCapt-win32-x64/`                                           | The unpacked packaged app (what both of the above contain)                                    |

`npm run record:artifacts` writes sizes, SHA-256 and the installer's Authenticode status to `docs/evidence/phase10/artifacts.json` and `out/make/SHA256SUMS.txt`. No MSI is built (`noMsi`). Builds are not bit-for-bit reproducible (the archives embed timestamps); the Electron zip and FFmpeg downloads are pinned by SHA-256.

`premake` runs `scripts/clean-build.mjs` (removes `.vite`, so a leftover E2E/mock build can never be packaged) and `scripts/fetch-ffmpeg.mjs` (idempotent, hash-verified).

## Packaged layout

```
FrameCapt.exe                         Electron runtime, fuses applied, icon + version info (company/product PROVISIONAL)
resources/app.asar                   .vite/build/main.cjs, preload.cjs, renderer (index.html + assets)
resources/ffmpeg/win32-x64/          ffmpeg.exe, ffprobe.exe, LICENSE, PROVENANCE.json, README.txt
LICENSE, LICENSES.chromium.html      Electron / Chromium notices
```

The FFmpeg folder is `resources/ffmpeg/win32-x64/` (Packager copies `extraResource` entries by base name, so the brief's shorthand `resources/ffmpeg/ffmpeg.exe` is not the real path). `resolveFfmpeg()` uses exactly this path, never `PATH`.

How resources resolve when packaged: the renderer is served by the `app://framecapt` protocol from `app.asar`; the preload is `app.asar/.vite/build/preload.cjs`; FFmpeg is found through `process.resourcesPath`. Verified on the installed app: the UI renders, `ffmpeg ok 9.0.2` is logged at start, a real recording is remuxed with the bundled FFmpeg and exported to H.264 MP4.

Fuses (read back from the **installed** exe by `smoke:installed`): RunAsNode off, cookie encryption on, NODE_OPTIONS off, `--inspect` off, embedded asar integrity on, only load from asar, **`GrantFileProtocolExtraPrivileges` off**.

## Identity (PROVISIONAL)

`forge.config.ts` marks these as provisional; the owner must confirm or replace them before any public release: product name `FrameCapt`, publisher/company `FrameCapt contributors`, app id `com.framecapt.app` (packager `appBundleId`, non-Squirrel AppUserModelID), Squirrel package id `FrameCapt` (also the install folder and the Squirrel AppUserModelID `com.squirrel.FrameCapt.FrameCapt`), the icon `assets/app/framecapt.ico` (the owner's logo, generated by `npm run brand:assets`, 16-256 px; the name and logo are reserved brand assets, see licensing.md).

## Install (per user, no administrator rights)

`FrameCapt-Setup-<v>.exe` (interactive) or `FrameCapt-Setup-<v>.exe --silent`:

| What                                                | Where                                                                                                                                                                   |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Program files                                       | `%LOCALAPPDATA%\FrameCapt\app-<version>\` plus `Update.exe`, the `FrameCapt.exe` launch stub and `packages\`                                                            |
| Start Menu shortcut                                 | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\FrameCapt contributors\FrameCapt.lnk`                                                                                  |
| Desktop shortcut                                    | `%USERPROFILE%\Desktop\FrameCapt.lnk` (created by Squirrel)                                                                                                             |
| Programs and Features entry                         | `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\FrameCapt` (runs `Update.exe --uninstall`)                                                                    |
| Launch at login (only when switched on in Settings) | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `com.squirrel.FrameCapt.FrameCapt`: `Update.exe --processStart FrameCapt.exe --process-start-args --hidden` |

Observed on this host: a silent install takes about 6 s. **A silent install does not start the app** (Squirrel launches the app with `--squirrel-firstrun` only after an interactive install); `smoke:installed` therefore starts `FrameCapt.exe --squirrel-firstrun` itself to prove that flag starts the UI normally (it used to quit: fixed).

Squirrel runs the app with `--squirrel-install` / `--squirrel-updated` (create shortcuts and exit), `--squirrel-uninstall` (remove shortcuts and the launch-at-login entry, ask whether to remove user data, exit) and `--squirrel-obsolete` (exit); `src/main/squirrel.ts` handles them without starting the UI (spawn with `shell: false`).

### Defect found and fixed: the installer made a network request

electron-winstaller's default nuspec has an `<iconUrl>` that Squirrel downloads while installing (for the Programs and Features icon). With no route to raw.githubusercontent.com the install waited **about 85 s** for a timeout. An offline app should not touch the network while installing, so `assets/app/framecapt.nuspectemplate` omits it: the install now takes about 6 s and Programs and Features shows a generic icon until the owner hosts an https icon (`iconUrl`).

### Defect found and fixed: launch at login did not start the app

Following the Electron docs literally (`args: ['--processStart', '"FrameCapt.exe"', '--process-start-args', '"--hidden"']`), Electron 44 writes the arguments quoted and escaped, so Update.exe was asked to start a file named `"FrameCapt.exe"` (with the quote characters) and nothing started. Measured: the quoted form starts nothing, the plain form (`--processStart FrameCapt.exe --process-start-args --hidden`) starts the app. `loginItemOptions` passes plain arguments; `smoke:installed` switches the setting on in the installed app, reads the Run value, executes it like Windows does and checks that the app starts hidden in the tray.

## Uninstall

`Update.exe --uninstall -s` (also what Programs and Features runs). Verified on this host:

- Removed: the program files, both shortcuts, the Programs and Features entry, the launch-at-login entry.
- **Asked, default Keep**: the uninstall hook asks "Remove your FrameCapt data too?" (Keep my data / Remove; no answer within 8 s means Keep). Keep leaves `%APPDATA%\FrameCapt` (settings, history database, unfinished sessions, logs) and every capture folder (`Pictures\FrameCapt`, `Videos\FrameCapt`, or the folders chosen in Settings) untouched, and a reinstall continues where it left off. Remove deletes `%APPDATA%\FrameCapt`; the box "Also move my screenshots and recordings to the Recycle Bin" (unchecked by default) additionally sends the captures to the Recycle Bin (a default folder as a whole only if it holds nothing but FrameCapt's own files, otherwise only the files listed in history). No question is asked while FrameCapt is running, when there is no data folder, or when `FRAMECAPT_UNINSTALL_KEEP=1` is set. `smoke:installed` sets that variable, puts sentinel files in both default capture folders and in `%APPDATA%\FrameCapt`, and checks them afterwards. The dialog itself needs a person and is a manual check (see ADR-034).
- Known Squirrel.Windows behavior, not a FrameCapt defect: the running updater cannot delete itself, so about 3.8 MB remain in `%LOCALAPPDATA%\FrameCapt` (`Update.exe`, a `.dead` marker, `app-<v>\squirrel.exe`) and an empty `FrameCapt contributors` Start Menu folder is left. No FrameCapt file (exe, asar, FFmpeg) remains. Deleting that folder by hand is safe.

To remove user data later (after choosing Keep, or with the portable zip), delete `%APPDATA%\FrameCapt` (the capture folders are yours: delete them only if you mean to).

## Data locations

| Location                                           | Holds                                                                                     | On uninstall                                  |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------- |
| `%LOCALAPPDATA%\FrameCapt`                         | The program (Squirrel)                                                                    | removed (stub remains)                        |
| `%APPDATA%\FrameCapt`                              | `settings.json`, history, `recordings`/`shots` sessions, `logs\main.log`, Chromium caches | kept unless you choose Remove                 |
| `Pictures\FrameCapt`, `Videos\FrameCapt` (default) | Screenshots, recordings, MP4 exports                                                      | kept unless you also tick the Recycle Bin box |
| `HKCU\...\Run`                                     | Launch at login entry (optional)                                                          | removed                                       |

Output folders can be moved in Settings; the app never permanently deletes a capture: history cleanup and export leave files alone, and the uninstall option only moves them to the Recycle Bin.

## Network behavior

FrameCapt makes no network request by itself (no telemetry, no cloud, no update check). Measured, not assumed:

- e2e build, 60 s of use (`tests/e2e/network.spec.ts`): 0 requests outside app/framecapt-media/blob/data, 0 requests for the app's own network blocker to cancel, every TCP connection of the process tree loopback-only (10 samples). A positive control (a main-process request to an https address) is observed and cancelled, so the zero is a real measurement.
- Installed app, 60 s including a recording and an MP4 export (`smoke:installed`): no non-loopback TCP connection in the whole process tree (10 samples), nothing for the blocker to cancel.
- Updates are unconfigured: `autoUpdater` is never even loaded (unit test).
- Outside the app: the build downloads Electron and FFmpeg (hash-pinned); with no `iconUrl` the installer downloads nothing.

## Linux x64 (experimental)

Built and run in WSL2 Ubuntu 26.04 and on Xvfb; commands, packages and tests are in [building-on-linux.md](building-on-linux.md). **Both artifacts are UNSIGNED.**

| Artifact (`npm run make` on Linux)                 | Notes                                                                                                                                                         |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `out/make/deb/x64/framecapt_<v>_amd64.deb`         | `@electron-forge/maker-deb` 8.0.1. Package `framecapt`, section graphics, maintainer/homepage PROVISIONAL. About 192 MB (FFmpeg is about 345 MB uncompressed) |
| `out/make/AppImage/x64/FrameCapt-<v>-x64.AppImage` | `@reforged/maker-appimage` 5.3.1 (ISC licence, typed against maker-base 6/7 and working under Forge 8). About 263 MB                                          |
| `out/FrameCapt-linux-x64/`                         | The unpacked app; executable `framecapt` (lower case on Linux), `chrome-sandbox`, `resources/`                                                                |

Packaged layout (deb): `/usr/lib/framecapt/framecapt` (also `/usr/bin/framecapt`), `/usr/lib/framecapt/resources/{app.asar,ffmpeg/linux-x64/{ffmpeg,ffprobe,LICENSE,PROVENANCE.json},LICENSE,THIRD_PARTY_NOTICES.md,framecapt-logo-256.png}`, `/usr/share/applications/framecapt.desktop`, `/usr/share/pixmaps/framecapt.png`. The FFmpeg folder is copied by a `packageAfterCopy` hook in `forge.config.ts` for the platform being packaged only (no Windows `.exe` in a Linux package, no Linux binary in a Windows one). Executable bits survive in the `.deb` (verified with `dpkg-deb -c` and by running it).

The AppImage maker would download the moving `continuous` release of the AppImage runtime without checking it. `scripts/fetch-appimage-runtime.mjs` (run by `premake`) downloads the dated release `20251108` of `AppImage/type2-runtime` (MIT), checks its SHA-256 (`2fca8b44...ec260d`) and the maker is given that file (`runtime` option).

The `.deb` `Depends` are the maker's defaults (`libgtk-3-0, libnotify4, libnss3, xdg-utils, libatspi2.0-0, libdrm2, libgbm1, libxcb-dri3-0, libsecret-1-0` and a trash tool); on Ubuntu 24.04+ these resolve through the `t64` packages (installed and run on 26.04 with `apt`). `chrome-sandbox` is installed setuid root.
