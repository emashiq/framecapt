## 1. Project license

Framelet is licensed under **GPL-3.0-only**, the license proposed by the owner and already named in `package.json`. The canonical text in [`LICENSE`](../LICENSE) was downloaded unmodified from https://www.gnu.org/licenses/gpl-3.0.txt on 2026-10-02 (35,149 bytes, 674 lines; first line "GNU GENERAL PUBLIC LICENSE", "Version 3, 29 June 2007"; last paragraph is the pointer to the LGPL / `why-not-lgpl.html`).

**Check performed before adding the license** (the brief: preserve an existing license, check ownership):

- No `LICENSE`, `COPYING` or license header existed in the repository before phase 11; `package.json` already declared `"license": "GPL-3.0-only"`.
- All commits (11 at the time of the check) are authored by the owner (Ashiqur Rahman Emran). The repository is new; no code was imported from another project with its own license. Third-party code enters only through npm dependencies (see below) and the pinned FFmpeg download. No third-party icons, fonts (other than Inter) or images are included: the app icon and tray icons are generated by `scripts/generate-tray-icons.mjs`.
- Not verifiable by tooling: whether the owner wrote every line personally, or used code snippets from other sources. OWNER: confirm there are no snippets copied from projects with incompatible licenses.
- Copyright holder line: the repository does not name one yet (`package.json` says "Framelet contributors"). OWNER: decide the copyright notice text (for example "Copyright (C) 2026 <name>") to place in source headers/About; the GPL text itself needs none.
- There is **no CLA** and no relicensing of contributors' code ([CONTRIBUTING.md](../CONTRIBUTING.md)). The owner holds the copyright of their own code and could in principle sell or dual-license it, but contributions under GPL-3.0-only without a CLA could not be relicensed without each contributor's consent. OWNER: decide before accepting outside contributions if dual licensing is ever wanted.

## 3. Electron and Chromium

Electron 44.5.1 is MIT; Chromium and its bundled libraries are under many licenses, listed in `LICENSES.chromium.html`, which Electron places next to `Framelet.exe` in the packaged app (verified in `out/Framelet-win32-x64/`). Framelet distributes them unmodified, together with Electron's MIT `LICENSE`.

**Finding:** that packaged `LICENSE` file at the root of the app is **Electron's**, not Framelet's. Framelet's own GPL `LICENSE` and `THIRD_PARTY_NOTICES.md` are not currently copied into the packaged app or the installer. A GPL-licensed binary distribution should carry the license text and notices. Fixing it needs a packager change (for example listing both files in `extraResource` or the `afterCopy` hook in `forge.config.ts`), which is source code and was out of scope for this documentation phase. See OWNER-TASKS.

## 4. FFmpeg and the GPL source obligation

Full provenance: [ffmpeg.md](ffmpeg.md) and the table in [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

- Version 9.0.2, Gyan Doshi "essentials" Windows x64 static build, **GPL v3 or later** (`--enable-gpl --enable-version3`, no `--enable-nonfree`), verified from the binary by `scripts/fetch-ffmpeg.mjs` on every fetch and recorded in `PROVENANCE.json`.
- Framelet runs FFmpeg as a separate program through a command line (`spawn`, argument array, `shell: false`). It is not linked into the Electron app. The combined installer is a collective distribution of a GPL-3.0-only program and a GPL-3.0-or-later program, compatible with each other; both are GPLv3.
- **Corresponding-source obligation** (GPLv3 section 6): whoever gives out the installer or zip must give recipients the source of the exact FFmpeg binary inside it. Source references: https://ffmpeg.org/releases/ffmpeg-9.0.2.tar.xz (HTTP 200, 2026-10-02) and the build's own https://github.com/FFmpeg/FFmpeg/commit/946fcce07b, which the GitHub API resolved to `946fcce07b6dcd0331c8cc609192aeff5e1924f8`, the commit of the `n9.0.2` release tag. The Gyan binary also statically contains many external libraries (x264, x265, libvpx, libopus, libaom and others, full list in `PROVENANCE.json`) and was produced with Gyan's build scripts; the Corresponding Source includes those. I could not verify from official pages that a complete source package for this exact binary is published by its builder.
- **OWNER task: mirror the exact sources alongside each binary release** (or provide a written offer valid at least three years) and publish the offer text. Until this is done, do not publish binaries.
- An alternative that reduces the burden: ship a smaller FFmpeg built by the project itself with only the needed components (libx264 or none, native `aac`, WebM/MP4 muxers), documented with a build script, or drop MP4 export and the H.264 encoder.
- The installer also contains Squirrel.Windows (MIT) and the tools electron-winstaller vendors (7-Zip, NuGet and others). Their exact notices were **not inventoried**; verify before a public release.

## 4a. Source offer and downloads for release builds

Each release page should say: where the corresponding source of Framelet itself is (the tag in this repository), where the FFmpeg and library sources are mirrored, and the written offer. Paid or free, the same source obligations apply to the owner as distributor.

## 5. Codec and patent note (open question, no clearance claimed)

Framelet produces **VP9 + Opus in WebM** (the recording format, via the browser engine) and **H.264 (libx264) + AAC (FFmpeg native encoder) in MP4** (export). Questions for OWNER and legal review before any public or commercial release:

- Do H.264 and AAC patent pools (for example the licensors that administer them) require royalties or a license for distributing or selling software that contains an H.264/AAC encoder, or for distributing encoded content, in the owner's and the buyers' jurisdictions? Do the answers change when the software is free versus sold?
- Do VP9 and Opus have any patent-licensing obligations that matter for redistribution?
- Does Chromium's bundled media stack (inside Electron) introduce any additional obligations?
- Is the answer different for an offering sold in Bangladesh, the US, the EU and elsewhere?
- If the review says no, MP4 export can be turned off without breaking the app: the capability check reports it unavailable and WebM stays the deliverable (see [ffmpeg.md](ffmpeg.md)).

Framelet's documentation does not claim any of these codecs is cleared.

## 6. Keeping this current

Regenerate the notices whenever dependencies or the FFmpeg build change:

```
npx --yes license-checker-rseidelsohn --production --json > licenses.json
```

then update [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md), the table above and [ffmpeg.md](ffmpeg.md). The notices file is excluded from Prettier (`.prettierignore`) because it embeds license texts verbatim.
